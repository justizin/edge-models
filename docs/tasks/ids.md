# Task: intrusion detection / log triage

Honest framing: LLMs are a poor fit for real-time packet or flow IDS. Where a small model can plausibly help is triage of textual events: syslog, auth.log, web access logs, firewall drops. This task measures that, and always alongside two classical baselines that run in microseconds.

- Set: `bench/tasks/ids/dataset.jsonl`, generated by `gen_dataset.py` (deterministic seed). 163 lines, 63 malicious across 8 attack families (ssh brute force, external root login, SQLi, path traversal / scanner, sudo download-and-exec, port scan, UID 0 user creation, reverse-shell cron). Benign set includes deliberate near-misses (internal failed logins, normal sudo, firewall noise).
- Baselines (`baselines.py`, stdlib only so they run on a Pi or switch): regex rules (what an admin greps for) and a multinomial naive Bayes with 5-fold CV. On this synthetic set rules reach F1 1.0, which is the point: the set is easy, and an LLM that cannot match it has no business in the pipeline.
- LLM prompting: one-word MALICIOUS/BENIGN answer, temperature 0, 8 max tokens. Unparseable answers count as benign and are tallied.
- Metrics: precision/recall/F1 on malicious, per-family accuracy, median latency per line.
- Run: `.venv/bin/python bench/bench_server.py --task ids --model-id <id> --threads 12`

Next steps once the synthetic set is exhausted: real loghub samples (Linux, OpenSSH, Apache) and flow-feature baselines on CIC-IDS2017 / UNSW-NB15 with scikit-learn, which needs the uv venv, not the stdlib path.
